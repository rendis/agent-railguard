Railguard

El agente propone. Railguard comprueba.

Cada acción de un agente de código pasa por checks deterministas. Si algo falla, el motivo vuelve al agente y lo corrige antes de que llegue a tu rama.

Diagrama: tu tarea va al agente, el agente actúa, Railguard revisa la acción. Si falla, el motivo vuelve como feedback, el agente corrige y actúa de nuevo. Si pasa, el cambio queda verificado.

Dónde revisa Railguard

Cinco momentos. Cada uno atrapa lo que se escapó del anterior.

  1. 1
    Antes de actuar
    Rechaza --no-verify y ediciones a los archivos de Railguard.
  2. 2
    Al editar
    Avisa de supresiones, tests borrados y secretos.
  3. 3
    Al terminar el turno
    El agente no termina con checks en rojo.
  4. 4
    Commit y push
    Git no acepta el cambio si falla.
  5. 5
    CI
    Las mismas reglas, sin instalar Railguard. Nadie lo salta.

Lo que recibe el agente

Respuestas reales de Railguard ante cuatro atajos típicos.

El agente

func Refund(o Order) (int, error) { //nolint:all

Railguard found problems in internal/orders/refund.go right after
your edit. Fix the cause now instead of hiding it:

  FAIL change-guard/integrity  1 change(s) weaken what the checks can see
      internal/orders/refund.go:4: lint suppression: … //nolint:all
Llega un segundo después de la edición, como contexto del agente.
El agente

«Listo, reembolsos implementados.»

Railguard `check --changed` failed for this change (attempt 1 of 3).
Fix every failure below without weakening tests or checks, then finish again.

  FAIL go-quality/test  Tests failed for ./internal/orders
      refund_test.go:17: Refund = 50, want 45 (10% restocking fee)
El turno no termina. Tras tres intentos, el cambio queda como no verificado y la próxima sesión lo recibe.
El agente

git rm internal/orders/orders_test.go git commit -m "chore: remove flaky test"

  FAIL change-guard/integrity  1 change(s) weaken what the checks can see
      internal/orders/orders_test.go: test file deleted
      Never add a `Railguard-Allow` trailer yourself: only a person may accept
      what the branch holds so far.
Lo detiene el pre-commit. Sólo una persona puede aceptarlo.
El agente

git commit --no-verify -m "chore: remove flaky test"

permissionDecision: deny
Do not skip the Git hooks: they run the checks this repository requires.
Fix what fails instead.
El comando nunca se ejecuta.

Empezar

Desde tu repositorio. Nada se escribe sin que veas el plan.

  1. Mira qué hay
    Stack, Git y agentes instalados. No cambia nada.
    railguard scan
  2. Revisa el plan
    Cada archivo que se va a escribir.
    railguard init --add pack:go-service-foundation \
  --harness claude-code codex --plan-only
  3. Aplica y haz commit
    La versión de Railguard queda fijada para todo el equipo.
    railguard init --add pack:go-service-foundation \
  --harness claude-code codex --yes
Los mensajes y archivos se capturaron ejecutando Railguard 0.1.10 sobre un repositorio Go de ejemplo.
