# Review Go Quality

## Refute or validate a fixed candidate

1. **Snapshot.** Read instructions, specifications, contracts, and [review-workflow.md](references/review-workflow.md). Fix base, scope, authority, Git identity, and exact worktree diff. Stop when governed source or configuration changes. Complete when the reviewed set and applicable requirements are enumerated.
2. **Configuration.** Inspect repository pins, native configs, scopes, commands, and CI. When reviewing an `Apply` or `Repair` candidate or any configuration-readiness classification, load `configure-go-quality` in `Assess` mode once because it owns those state semantics. Otherwise load it only when readiness is missing, invalid, inherited, unpinned, or unclear enough to affect a claim. Never apply or repair during review.
3. **Signals.** Run or reuse native evidence only when snapshot, command, version, config, scope, and artifact match. Record `pass`, `fail`, `blocked`, `not evaluated`, or `unavailable` for every claimed dimension. A failed producer invalidates partial output. Resolve this skill's installed root for optional report-only `go-metrics`; never make the repository or CI depend on that path. Read [toolchain-and-deprecations.md](references/toolchain-and-deprecations.md).
4. **Design.** Read [go-quality-model.md](references/go-quality-model.md). Review from request and architecture toward detail. Challenge current need, existing capability, ownership, deterministic transformation versus effects, direct alternative, semantic duplication, pattern cost, compatibility, debt scope, naming, documentation value, and test sensitivity. A metric is an inspection candidate, not a finding.
5. **Adversary.** For delivery or an explicit adversarial request, read [adversarial-design-review.md](references/adversarial-design-review.md). Try to falsify every requirement, oracle, claimed simplification, and gate result. Use fresh context when available. Reject threshold gaming, coverage-only tests, weakened assertions, ceremonial patterns, equivalent syntax changes that reduce mutants, and unrelated cleanup.
6. **Findings.** Read [finding-format.md](references/finding-format.md). Verify the candidate's claimed outcome before issuing findings. Return actionable findings by severity or state that none exist. Each finding needs exact location, contract or execution evidence, impact, minimum correction, and verification. Keep unavailable or unassessed dimensions distinct from pass. An honestly classified blocked prerequisite is evidence, not an actionable finding; pass the candidate review when its in-scope work is correct and the blocked claim is independently supported. For configuration-only candidates, a pinned direct target that deterministically reports a missing behavioral proof such as fuzz and is truthfully classified `READY_WITH_FINDINGS` is working configuration, not broken wiring. Do not recommend deleting that target from the aggregate or ask configure to invent product tests.
7. **Handoff.** Do not fix findings. Report accepted remediation for development, which selects TDD, Go testing, configuration, or E2E and creates a new candidate. Review the new fixed snapshot only after remediation; do not run an indefinite review loop.

Use configured thresholds as mechanical policy but require contextual evidence before recommending a semantic refactor. A clean tool run cannot prove architecture, unambiguous names, useful GoDoc, necessary abstraction, or an independent test oracle.
